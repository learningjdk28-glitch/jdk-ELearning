## Protecting access
Use a strong, unique Wi-Fi password and modern network protection such as **WPA2**-AES or WPA3 when supported. Avoid sharing the password publicly.

Install legitimate software **updates** when available.

A secure Wi-Fi link protects wireless access. Users should still check site authenticity and prefer **HTTPS** for sensitive browsing.

## Troubleshooting by scope
First observe the symptom: is one device affected, or everyone?

- Check airplane mode, the Wi-Fi network selected, signal strength, cabling and router power.
- Check whether the internet service is down.
- Compare another device on the same network.
- Test local access and internet access separately.
- Avoid changing many settings at once.

## Safer decisions
Unknown public Wi-Fi networks can pose risks, especially if a network is impersonating a trusted access point.

- Verify the network name with staff.
- Do not ignore security warnings.
- Use trusted services.
- Never share credentials just because a login page asks. Verify the page and the organization first.

## Visual steps
- Start: only one device? | Ask whether one device is affected or everyone.
- Yes: check the device | Look at its Wi-Fi setting, the network chosen, or its cable.
- No: check the router or gateway | Look at router power and lights, then the internet service.
- Change one thing at a time | Test after each change and note the result.
- Do not reset yet | Do not reset until you understand what a reset will change.

## Example
A phone joins the Wi-Fi but cannot load pages. You test a second phone on the same network and it works. That points to the first phone, so you check its settings before touching the router.

## Practice
A phone connects to Wi-Fi but has no internet. Compare another phone, check the router indicators, verify the network, and write down which check narrowed down the cause.
